==============================================================
 LOJA — LANDING PAGE + CHECKOUT TRANSPARENTE PIX (MERCADO PAGO)
==============================================================

O QUE MUDOU NESTA VERSÃO
--------------------------------------------------------------
1. FRONT-END: Materialize CSS foi removido e substituído por Tailwind CSS v4
   (visual escuro, moderno e elegante). O CSS compilado fica em
   public/css/app.css e a fonte de estilos é src/input.css.

2. CHECKOUT: o Checkout Pro (redirecionamento) foi substituído pelo
   CHECKOUT TRANSPARENTE com UM único método de pagamento: PIX.
   O cliente recebe na própria página o QR Code + o código "copia e cola".
   Cartão, boleto e saldo Mercado Pago foram removidos.

3. ENTREGA AUTOMÁTICA: quando o pagamento é APROVADO o servidor envia
   automaticamente um e-mail com o botão/link de DOWNLOAD do script.
   O envio é idempotente (não duplica) e pode ser reenviado pelo painel.

4. PAINEL ADMIN (/dash): reformulado (sidebar, cards, gráfico, abas,
   tabelas com detalhes) e com uma nova seção "Link de download",
   onde você define o link que vai no e-mail.

5. BANCO: novas colunas/tabelas (link_download, email_enviado,
   valor_total, reembolsos). O servidor aplica sozinho na inicialização,
   mas você também pode rodar o SQL manualmente (veja abaixo).

6. ENTREGA GARANTIDA: o servidor agora verifica SOZINHO os pagamentos
   pendentes a cada poucos minutos (lib/reconciliacao.js), uma página
   /recuperar permite o próprio cliente reenviar o acesso e o checkout
   retoma um Pix em aberto quando o navegador é reaberto.
   Detalhes na seção "ENTREGA GARANTIDA" mais abaixo.

7. LOGS: todas as requisições HTTP passam pelo morgan e são registradas
   no console/painel com o método, a URL, o código de status e o tempo
   de resposta. Detalhes na seção "LOG DAS REQUISIÇÕES HTTP" mais abaixo.


COMO RODAR
--------------------------------------------------------------
1) npm install

2) Copie .env.example para .env e preencha:
     ACCESS_TOKEN        -> Mercado Pago (painel do desenvolvedor)
     DB_*                -> seu banco MySQL/MariaDB
     API_KEY             -> Mailgun (envio dos e-mails)
     MAILGUN_DOMAIN      -> domínio remetente no Mailgun
     SECRET              -> segredo da sessão
     SITE_URL            -> URL pública HTTPS do site (para o webhook)
     DOWNLOAD_LINK       -> link padrão de download (fallback do banco)

   Opcionais (recomendados):
     MP_WEBHOOK_SECRET   -> chave secreta da aplicação (valida o webhook)
     CRON_SECRET         -> token do cron externo que chama /tarefas/reconciliar
     RECONCILIACAO*      -> ajustes da verificação automática (padrões servem)

3) Banco de dados:
     - importe banco_de_dados_aqui/backup_tabelas.sql (se for um banco novo)
     - rode a migração:
       mysql -u USUARIO -p NOME_DO_BANCO < banco_de_dados_aqui/migracoes/001_pix_transparente_e_link_download.sql
       (o servidor também aplica essas alterações automaticamente)

4) CSS (só é necessário se você editar o visual):
     npm run dev:css     -> recompila o Tailwind ao salvar
     npm run build:css   -> gera o public/css/app.css minificado
   O app.css já vai commitado, então em produção basta `npm start`.

5) Subir o servidor:
     npm start           (ou `npm run dev` com nodemon)


MODO DEMONSTRAÇÃO (sem banco e sem credenciais)
--------------------------------------------------------------
   DB_MOCK=true MP_MOCK=true npm start

 - DB_MOCK=true : usa um banco em memória com dados fictícios
 - MP_MOCK=true : simula o Mercado Pago (QR Code fictício que é
                  "aprovado" depois de ~15 segundos)
Útil para ver o layout e testar o fluxo do Pix. NUNCA use em produção.


WEBHOOK DO MERCADO PAGO (importante!)
--------------------------------------------------------------
O aviso de pagamento aprovado chega por webhook. Sem ele o sistema ainda
funciona (a página fica consultando o status a cada 4s), mas o e-mail
pode atrasar se o cliente fechar a página.

1. Acesse https://www.mercadopago.com.br/developers/panel/applications
2. Abra a sua aplicação -> Webhooks
3. Em "Pagamentos" informe:  https://SEU-DOMINIO/webhook
4. Salve. O SITE_URL do .env precisa ser o mesmo domínio (HTTPS).
5. (Opcional) Copie a "chave secreta" da aplicação para MP_WEBHOOK_SECRET
   no .env. Com ela o servidor valida a assinatura x-signature e recusa
   notificações falsas. Sem ela, a validação fica desligada.

ATENÇÃO ao plano gratuito do Render: a instância "dorme" após alguns
minutos sem acesso e leva ~1 minuto para acordar. Como o Mercado Pago
espera poucos segundos pela resposta do webhook, a notificação pode ser
perdida. A verificação automática resolve isso, mas para o site responder
rápido ao cliente vale manter a instância acordada:
  - crie um cron gratuito (ex.: https://cron-job.org) chamando
    https://SEU-DOMINIO/health a cada 10 minutos; e/ou
  - use o mesmo cron para chamar, a cada 5 minutos,
    https://SEU-DOMINIO/tarefas/reconciliar?token=SEU_CRON_SECRET
    (POST ou GET). Configure CRON_SECRET no .env.


ENTREGA GARANTIDA (verificação automática)
--------------------------------------------------------------
O problema que isso resolve: o cliente paga pelo app do banco, o
navegador fecha (celular com pouca memória) e o webhook do Mercado Pago
não chega — o pedido ficava "pendente" para sempre e o e-mail não saía.

Agora o próprio servidor roda a cada RECONCILIACAO_INTERVALO_MINUTOS
(padrão: 5 min):

  1. pega os pedidos recentes que ainda estão pendentes (e também os
     aprovados que ficaram sem e-mail enviado);
  2. consulta cada um no Mercado Pago pela API;
  3. atualiza o status no banco e dispara o e-mail com o link de
     download quando aparece "approved".

Também foi adicionado:

  - Botão "Já fiz o pagamento — verificar agora" no checkout, que força a
    consulta na hora (POST /pagamento/verificar/:pedidoId).
  - Retomada do Pix: o pedido em aberto fica salvo no navegador e
    reaparece com o mesmo QR Code se o cliente reabrir a página. Ao
    voltar para a aba, o status é consultado imediatamente.
  - Página pública /recuperar: o cliente informa e-mail + CPF e recebe o
    link de download novamente, sem precisar falar com o suporte. Antes
    de responder, o servidor também consulta o Mercado Pago.
  - Painel (/dash -> Link de download -> "Rede de segurança do Pix"):
    mostra a última/próxima verificação e tem o botão
    "Verificar pendentes agora" (POST /painel/verificar-pendentes).
  - Gatilho para cron externo: POST|GET /tarefas/reconciliar?token=...
    (token = CRON_SECRET ou o SECRET da sessão).
  - GET /health passou a mostrar o estado da verificação automática.

Para desligar a rotina: RECONCILIACAO=off no .env.


FLUXO DO PAGAMENTO
--------------------------------------------------------------
1. O cliente preenche nome, e-mail e CPF na landing page.
2. POST /pagamento/pix cria o pagamento no Mercado Pago e devolve
   qr_code (copia e cola) + qr_code_base64 (imagem) + expiração.
3. A página mostra o QR Code e consulta GET /pagamento/status/:pedidoId
   a cada 4 segundos (e na hora em que a aba volta a ficar visível).
4. O Mercado Pago chama POST /webhook quando o status muda.
5. Status "approved" (uma única vez) -> e-mail com o link de download.
6. Se 3 e 4 falharem (cliente fechou tudo / webhook não chegou), a
   verificação automática encontra o pagamento em poucos minutos e
   envia o e-mail do mesmo jeito. O envio é idempotente: nunca duplica.

LOG DAS REQUISIÇÕES HTTP (morgan)
--------------------------------------------------------------
Toda requisição recebida pelo servidor é registrada no console (e no
painel de logs do Render, em produção) com o método, a URL, o CÓDIGO DE
STATUS da resposta e o tempo de processamento. Serve para acompanhar
erros 4xx/5xx, lentidão e as chamadas do webhook do Mercado Pago.

O formato se adapta ao ambiente:
  produção (NODE_ENV=production) -> "combined" (padrão Apache, com IP e
                                    user-agent, pronto para o log do Render)
  npm test                       -> "tiny"    (compacto)
  local (npm start / npm run dev)-> "dev"     (uma linha colorida por acesso)

Para escolher outro formato, defina LOG_FORMATO no .env — aceita os
formatos do morgan (tiny, short, common, combined) ou um personalizado,
ex.: LOG_FORMATO=":method :url :status :response-time ms - :remote-addr".
